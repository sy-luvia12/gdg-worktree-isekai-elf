# src/api

화면이 부르는 API를 모은 곳. 번호(C-1 등)는 노션 API 초안 번호.

- `index.ts`: 화면이 쓰는 함수와 응답 타입. 함수마다 바꿀 `supabase-js` 호출을 주석으로 달아 둠.
- `dummy.ts`: API 초안 응답 예시 모양 그대로 돌려주는 더미. 저장은 메모리에만.

**supabase 붙일 때:** `index.ts` 각 함수 몸통을 주석의 호출로 바꾸고 `dummy.ts`를 지운다. 화면 코드(`src/app/index.tsx`)는 그대로 둔다.

## 화면별로 쓰는 API

| 화면 | 하는 일 | API |
| --- | --- | --- |
| 상층부 | 반려식물 보여주기 | U-2 목록 → U-3 상세(엘프 찾기용) |
| 상층부 | + 깃발: 반려식물 등록 | P-1 업로드 → I-1 식별 → U-1 등록 |
| 상층부 | 반려식물 눌러서 건강검진 | P-1 업로드 → H-1 검진 |
| 홈(하층부) | + 깃발: 식물 수집 | P-1 업로드 → I-1 식별 → I-2 수집 저장 |
| 홈(하층부) | 메인 캐릭터 고르기 | C-2a(모은 식물류) · 저장할 API 없음 ↓ |
| 비석 | 가계도 아이콘 켜기, 눌러서 설명 | C-1 + C-2a |
| 샘 | 식별·검진 기다리는 동안 미미르 표시 | 없음 |

화면이 아직 없어서 안 쓰는 API: A-1 로그인, P-2 사진 URL, I-3a·I-3b 수집 기록(홈에 최근 수집 목록이 아직 없음), C-2·C-3·C-4 도감 상세, U-4·U-5 반려식물 수정·삭제, L-1~L-4 돌봄 기록, H-2·H-3 검진 기록.

## API에 없는 값 (이예주 님 공유용)

1. **홈 메인 캐릭터 저장 칸이 없음.** 사용자가 모은 엘프 중 하나를 홈에 세우는데 저장할 곳이 없어서, 지금은 앱을 끄면 처음 값으로 돌아감.
   제안: `profiles.main_character_id`(text, `characters.id` FK, nullable)를 추가하고 `from('profiles').update({ main_character_id })`로 저장.
2. **U-2 `user_plant_status`에 `species_id`/`character_id`가 없음.** 상층부에 반려식물 엘프 그림을 그리려면 식물마다 U-3을 한 번 더 불러야 함.
   제안: 뷰에 `species_id`와 `character_id`(`plant_species.character_id`) 칼럼 추가.
3. **`characters` 코드가 디자이너 확정본과 다름.** 문서 2장 가계도는 `p50`·`p61`·`p62`·`c61x`·`c62x`. 협의 답변에서 디자이너가 확정한 코드는 진정쌍떡잎 `p51`(`c511`~`c515`), 단자엽 `p52`(`c521`~`c524`), 초기 분화군 `p55`(`c555`)이고, `p51`·`p52`의 부모는 속씨 `p40`임. 앱은 확정본 기준이라 시드와 문서를 맞춰야 함.
4. **확인:** 부모 노드는 활성 전과 후의 그림이 다른데 `characters.image_path`는 하나뿐. 그림을 앱에 두는 것으로 보고 지금은 앱에 둠. 서버에서 내려줄 거면 칸이 하나 더 필요함.
5. **확인:** 부모 노드는 바로 아래 노드가 모두 활성화돼야 활성화되는 규칙이라, 이끼류(`c111`~`c113`)를 식별로 못 모으면 선태식물 `p11`과 루트 `p00`은 영원히 꺼져 있음. 이끼 수집 방식이 정해지면 같이 정리 필요.

## 앱 쪽에 아직 없는 것 (API 문제 아님)

- I-1 후보 고르는 화면이 없어 1순위를 자동 선택함.
- U-1 별명 입력 화면이 없어 종 이름을 별명으로 넣음.
- 업로드 전 긴 변 1280px 줄이기가 없음(촬영 품질 0.7만 맞춤).
- 로그인(A-1)이 없음. supabase 붙일 때 같이 필요함.
